Experimental Features
=====================

.. This page is generated by shaders/scripts/generate-stability-docs.mjs from
   the stability registry and docs/shaders/experimental-features.json.

These are new features that exist to seed the Noisemaker 2.x feature set. Node names, keywords, defaults, argument shapes, and rendered output may all change without a deprecation period. There is no flag to turn them on.

The scene vocabulary
--------------------

``scene``

``scene()`` adds a third dimension to the Polymorphic DSL. A scene program describes a camera, lights, and a hierarchy of meshes and volumes with PBR materials.

Current limits: One ``scene()`` per program, one ``environment()``. Primitives only; no loaded models inside ``scene()``. The camera cannot be animated from the DSL; a light's position and direction cannot either. A program re-emitted from its parsed form comes back with the whole ``scene()`` on one line and its interior comments removed.

See :ref:`The scene vocabulary <shader-scene>`.

The deferred renderer
---------------------

``scene.deferred``

The renderer that draws ``scene()`` programs. It fills a G-buffer from the mesh hierarchy, lights it once in screen space with a Cook-Torrance BRDF, adds ambient occlusion and reflections, tonemaps, and presents into a texture the 2D pipeline then treats as an ordinary source.

Current limits: One ``reflector()`` per scene. No cast shadows.

See :ref:`The deferred renderer <shader-deferred-rendering>`.

Volume nodes
------------

``scene.volume``

``volume()`` places a density volume in the scene graph. Its positional argument is one of the pipeline's eight volume surfaces, so a 3D program that fills an atlas with ``write3d()`` becomes a node beside the meshes rather than a separate fullscreen marcher with its own camera and lights.

Current limits: ``volume()`` samples a fixed 64-cube atlas.

See :ref:`Volume nodes <shader-scene-volumes>`.

External inputs in scenes
-------------------------

``scene.inputs``

Transform components and light intensity accept ``midi()`` for a MIDI channel and ``audio()`` for a frequency band, in place of numbers.

Current limits: Descriptors on ``pos``, ``scale`` and ``intensity`` produce ``0..1``.

See :ref:`External inputs in scenes <shader-scene-animation>`.

Cubemap export of scenes
------------------------

``scene.cubemapExport``

A ``scene()`` program exports a cubemap through the same ``renderCubemap()`` API as a cubemap-renderer program.

Current limits: Faces are never tiled, and a configured reflection probe is captured once for the first face and frozen for the rest. A second export started before the first settles is rejected.

See :ref:`Cubemap export of scenes <shader-scene-cubemap-export>`.

Tiled export of scenes
----------------------

``scene.tiledExport``

``setTileRegion`` tiles a scene by restricting the camera to the tile's sub-frustum.

Current limits: SSAO can seam within its kernel's projected reach, and local screen-space reflections cannot be tiled at all. The reflection probe is never tiled.

See :ref:`Tiled export of scenes <shader-scene-tiled-export>`.

glTF loading
------------

``gltf``

``loadGLTFFromURL()`` and ``loadGLTFFromString()`` load glTF and GLB mesh files. Each takes the target surface as its second argument, defaulting to ``mesh0``.

Current limits: Loaded models cannot be placed in a ``scene()``.

See :ref:`glTF loading <shader-language-gltf>`.

Mixed argument order
--------------------

``lang.mixedArguments``

Keywords claim their own parameter slots by name, wherever they appear in the call. The positionals are then bound in source order to the slots no keyword claimed, left to right.

See :ref:`Mixed argument order <shader-language-mixed-arguments>`.

Object literals
---------------

``lang.objectLiteral``

``{ key: value }`` is an expression.

Current limits: No call takes an object as a value yet.

See :ref:`Object literals <shader-language-object-literals>`.
